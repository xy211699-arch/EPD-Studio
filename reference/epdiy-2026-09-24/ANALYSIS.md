## 范围与限制

本目录保存了主页直接引用的 HTML、单个应用 JavaScript 包、CSS 和 favicon。HTML 还会在运行时加载百度统计脚本；该第三方脚本不是墨水屏应用协议的一部分，没有归档。应用 JS 未发现动态 `import()`、Worker 或 Service Worker，CSS 未发现 `@import`。这只支持“当前页面直接引用的前端静态资源已保存”，不等于获得未打包的 React 工程、全部历史版本或服务端源码。`index-DJ17L3Pz.js.map` 返回 HTTP 404。未调用写设备命令，也未上传图片或固件。

## 设备识别与连接

站点通过 Web Bluetooth 的 `requestDevice()` 弹出首次连接选择器，连接后使用 GATT 服务 `62750001-d828-918d-fb46-b6c11c675aec` 和特征 `62750002-d828-918d-fb46-b6c11c675aec`。它保存本次页面中的 BluetoothDevice 对象；“重连”使用该对象重新调用 `gatt.connect()`，不重新弹出设备选择器。断开连接后页面清理会话状态。该方式只在浏览器持有设备对象时适用，不代表永久自动配对。

## 驱动、颜色和画布

设备配置通知的第 8 字节（索引 7）被转换为驱动编号，再从前端驱动表自动选择颜色模式和画布。该版本驱动表包含 `0x16`，标记为 `4.2寸(三色,SSD1683)`，颜色模式 `BWR`，画布 `4.2_400_300`（400 × 300）。这确认的是站点所采用的映射，不能仅凭网页代码独立证明实体屏驱动芯片的丝印型号。2026-09-24 对照前，本地页面的驱动表缺少 `0x16`，因此无法按该映射完成配置匹配。

## 上传路径

用户提供图片后，前端先绘制到 Canvas，按选定颜色模式执行抖动与像素打包。上传时先发送 `INIT`（命令 1），等待约 200 ms，再发送 `WRITE_IMG`（命令 48）数据包；每包图像载荷上限按协商 MTU 减 2 计算。设备报告 `rle=1` 时，站点仅在压缩后更短时使用 RLE。对 `0x16` 对应的 `BWR` 模式，站点把图像拆成黑白、红色两个平面依次发送，最后发送 `REFRESH`（命令 5）。代码会统计失败数据包并提示用户，但仍可能发送刷新命令；这一行为不应无条件照搬到本地页面。

## 图片槽位与服务器依赖

通知 `slots=N mask selected` 会更新图片槽位数、已占用位掩码和当前槽位。上传按钮在 `N>0` 时要求选择槽位；若槽位已占用，会提示覆盖，之后先发送 `SET_SLOT`（命令 49，参数 `[0, selected]`），才进入图片上传。用户先前提供的 `slots=15 1 0` 与该流程相符。2026-09-24 对照前，本地页面没有显式槽位设置流程；但仅凭静态代码不能断定这就是先前屏幕异常的成因。

前端收到 `sid=` 通知后会向本站 `POST /ecc/check` 提交 `hash`；校验失败时，前端会报错并断开。模板列表、模板渲染和文字渲染分别使用 `GET /builtin`、`POST /render` 和 `POST /render-text`。这些服务端实现没有包含在前端包内，因此不能声称已读取“网站的所有源代码”，也不能假定本地离线复制能等效实现其服务器功能。本次分析没有提交设备 SID，也没有请求上述服务端接口。

## 与当前本地页面的差异及后续边界

对照前，本地页面沿用先前参考站点的驱动列表，缺少 `0x16`；它要求设备配置与选项严格一致，因此用户这台设备会被挡在上传前。2026-09-24 已按本分析补齐 `0x16` 映射、设备当前槽位的覆盖确认与 `SET_SLOT`、`INIT` 后约 200 ms 的等待，并将默认确认间隔对齐为 10；保留写包失败即中止且不刷新的保护。上述行为已通过无设备测试，实体屏幕显示仍需用户手动连接验收。不要把驱动切换、清屏、固件升级或服务端 SID 校验当成普通图片上传的必要步骤。
