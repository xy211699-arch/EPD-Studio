# 墨水屏每小时自动发送桌面应用设计

## 目标

本阶段交付一个可双击启动的 Windows 桌面应用。应用启动后立即主动连接墨水屏并发送固定测试图，首次发送完成后每隔 60 分钟再次发送。用户关闭应用后，自动发送任务立即停止；再次启动应用时重新立即发送一次，不补发应用未运行期间错过的任务。

本阶段只验证本地桌面应用、原生 BLE 主动连接和周期传图是否稳定。自定义版式、Codex 额度、日期和电子宠物不在本阶段范围内。

## 已确认的设备信息

目标设备在 Windows 缓存中的名称为 `NRF_EPD_9691`，用户可见名称为 `NRF-EPD-9691`，蓝牙地址为 `CC:5C:27:AE:96:91`。EPD 主服务 UUID 为 `62750001-d828-918d-fb46-b6c11c675aec`，主要写入特征 UUID 为 `62750002-d828-918d-fb46-b6c11c675aec`。

原生连接探测已经至少一次成功连接并发现上述服务与特征，但也观察到一次连接超时。因此正式应用必须实现连接释放、超时、有限重试和清晰日志，不能把单次连接成功作为稳定性结论。

## 技术方案

应用使用 Python 3.13、PySide6、Bleak 和 Pillow 开发，并使用 PyInstaller 打包为 Windows 桌面应用。PySide6 主线程只负责界面与定时状态，BLE 连接和图片传输在后台工作线程运行，任何蓝牙等待或重试都不得阻塞界面。

应用不依赖 `epdiy.cn`、Edge 或 Web Bluetooth，也不触发浏览器设备选择器。BLE 层使用固定设备地址主动建立连接，并在每次发送结束后释放 GATT 会话，避免长期占用设备。

## 用户界面

初版窗口显示应用运行状态、目标设备、当前连接阶段、上次发送时间、上次发送结果、距离下次发送的剩余时间和滚动日志。窗口提供“立即发送”“启动自动发送”和“停止自动发送”三个操作。

应用启动时自动进入运行状态并立即发送。关闭窗口代表完全退出，不继续在系统托盘或后台运行。第一阶段不提供图片选择器、设备选择器、启动项设置或托盘模式。

界面视觉要求为简约、美观和功能清晰。窗口使用单列信息层级：顶部突出当前运行状态和下一次发送倒计时，中部展示固定测试图预览与最近一次发送结果，底部放置三个主要操作和可折叠日志。视觉样式使用克制的中性色、单一强调色、一致的圆角与间距，不使用装饰性动画、渐变背景或多余图标。连接、发送、成功和失败状态同时使用文字与颜色表达，不能只依赖颜色。

## 调度行为

启动应用后立即创建一次发送任务。发送成功后从成功完成时刻开始计算 60 分钟；倒计时到期后创建下一次发送任务。手动点击“立即发送”并成功后，也从该次成功时刻重新开始 60 分钟倒计时，避免短时间内重复刷新。

单次计划发送失败时，应用最多尝试三次。每次失败都先彻底释放当前 BLE 客户端，再经过短暂退避后重新连接。三次均失败时，本轮记为失败，并从失败结束时刻开始新的 60 分钟周期，防止持续重试耗尽电量或占用蓝牙。

“停止自动发送”只取消后续计划任务，不中断已经开始的单次发送，以避免在数据传输过程中破坏设备状态。“启动自动发送”在停止状态下会立即发送一次，而不是等待 60 分钟。

## 图片与协议

第一阶段固定使用项目内的 `epd_ble_test.png`，当前尺寸为 400×300，内容为 `BLE TEST`、简单笑脸和设备名称。应用启动时验证文件存在、尺寸正确且可解码，验证失败时在界面显示错误并停止本轮发送。

图片转换和 BLE 命令必须与 `epdiy.cn` 当前实现及设备固件协议一致。实现前需要从公开上位机代码中确认黑白位图排列、阈值处理、初始化命令、分包格式、应答条件和完成判定。当前公开固件没有提供“墨水屏已经完成物理刷新”的回执，因此程序只能在全部图片分包以及 `REFRESH` 命令均被 GATT 接受后，把本轮标记为“传输完成，屏幕刷新中”，不能声称已经程序化验证物理渲染结果。带响应写入检查点和最终 `REFRESH` 写入失败都必须判定为发送失败；最终画面是否正确仍由实体设备验收确认。

## 错误处理与日志

应用需要区分设备未缓存、蓝牙关闭、连接超时、服务缺失、特征缺失、写入失败、设备应答超时、图片无效和任务已停止。用户界面显示简明中文状态，日志同时记录时间、尝试序号、执行阶段、耗时和底层异常文本。

应用不得自动修改 Windows 蓝牙设置。设备不可用时保持界面可操作，并允许用户点击“立即发送”重新尝试。

## 测试策略

自动测试使用依赖注入隔离真实蓝牙和真实时钟。调度测试通过虚拟时钟瞬间推进时间，不会真实等待 60 分钟。测试覆盖启动立即发送、59 分钟不发送、推进到 60 分钟后发送、手动发送成功后重置周期、停止后不再调度、重新启动自动发送时立即执行、失败最多重试三次、每次重试前释放连接以及连续失败后进入下一周期。

协议测试使用固定的小型像素图和记录型传输对象，验证像素编码、命令顺序、分包边界、带响应写入检查点、最终 `REFRESH` 写入和错误应答，不依赖实体设备。界面测试验证运行状态、按钮启用状态和后台任务完成后的状态更新。

实体设备验证分为三个阶段。首先运行一次性发送，确认 `epd_ble_test.png` 能在不打开浏览器的情况下显示；其次把测试构建的间隔临时设为较短值验证多轮连接、发送和释放；最后恢复正式的 60 分钟配置，生成 Windows 可执行程序并由用户进行长时间运行验证。

## 交付物

源代码包含界面、调度器、BLE 连接器、EPD 协议编码器和自动测试。项目提供开发环境安装、运行测试、启动应用和打包可执行程序的命令，并生成一个用户可双击启动的 Windows 应用构建产物。

诊断阶段的 `ble_scan_probe.py`、`ble_cached_probe.py` 和 `ble_connect_probe.py` 保留为开发证据，但不作为最终用户界面或正式运行入口。

## 非目标

本阶段不读取 Codex 额度，不生成日期或电子宠物，不允许更换图片，不设置 Windows 开机自启动，不在系统托盘运行，不支持多台墨水屏，也不修改设备固件。
