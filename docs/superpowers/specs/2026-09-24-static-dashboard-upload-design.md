# 静态三色看板与双视图上传设计

## 状态与目标

本文件将用户已同意的页面方案落实为实施规格，等待用户审阅后再编写实施计划及产品代码。目标是在既有本地 Edge 网页最上方增加“图片上传”和“自定义图片上传”两个切换选项。原图片上传视图保持当前功能和默认入口；新视图以原生 400×300 黑白红点阵静态复现工作区根目录的“参考图片.png”所示布局，并允许用户预览后手动发送到同一设备。

参考图片是实体屏照片，不是原始点阵。第一版复现其布局、文字层级、配色和像素宠物的视觉效果，而不声称能从照片恢复完全相同的原始像素。示例日期、5 小时与 7 天额度以及刷新时间均为静态演示值；不读取 Codex 账户、不自动更新时间、不做定时上传。

## 依据与边界

EVA-CLIENT 的公开控制台使用深色设备状态栏、暖灰背景、白色卡片与浅色胶囊形标签栏。当前本地页面已经采用其主要配色，因此只扩展导航和新视图，不整体替换现有界面。参考来源为 `https://github.com/Noietch/EVA-CLIENT/blob/main/src/core/app/console/static/index.html` 与同目录的 `css/console.css`；借鉴视觉规则，不直接复制控制台的机器人功能或整套代码。

开源 EPD-nRF5 的 `GUI/GUI.c` 用位图字体和图形原语在目标分辨率逐像素绘制日历，`GUI/Adafruit_GFX.c` 维护黑白与红色缓冲，`EPD/EPD_service.c` 将设备端日历绘制与蓝牙图片写入分开。该仓库仅作为点阵绘制方法的参考，不能假定它与用户设备正在运行的固件完全同版。设备侧传输应继续以已通过实体屏验收的本地上传链路及 `https://epdiy.cn/` 当前公开前端为准，不修改固件、引脚或驱动设置。

## 页面结构与状态

保留当前状态栏中的设备名称、连接状态和本地运行标识；在状态栏与引导条之间添加可键盘操作的双选项标签栏。初次打开默认显示“图片上传”，原操作卡片、文件选择、裁剪、抖动、预览、日志及高级参数保留。切换只显示或隐藏同一 HTML 文档中的视图，不跳转 URL、不重新加载页面，所以浏览器当前持有的 BluetoothDevice 与 GATT 会话得以保持。切换本身不得调用任何蓝牙方法。

标签采用 EVA 风格的浅色胶囊、活动底色、小号序号与橙色选中标记，交互语义提供选中状态、可见焦点及键盘切换。两个视图分别保存图像状态：普通视图保持文件、裁剪和抖动结果；自定义视图保存其独立的静态生成画布。切回普通视图后不丢失所选文件及预览；切回自定义视图后不重新生成或上传，除非用户明确点击生成。传输进行期间保持状态可见，并阻止第二次上传及可能隐藏当前传输状态的视图切换。

新视图使用与旧视图一致的两栏卡片结构，窄窗口改为上下排列。左栏解释静态示例和操作边界，提供“生成参考点阵”与“上传到墨水屏”两个明确动作；右栏以原生 400×300 像素预览画面、展示当前生成/连接/发送状态。静态示例不用文件选择框，也不显示无意义的抖动与裁剪选项。新视图左栏另设“连接”“重连”按钮，调用既有处理函数并遵守既有启用条件；顶部设备状态栏始终可见，不要求用户切回旧视图才能查看或恢复连接。

## 点阵生成与图片来源

生成器在独立画布上按 400×300 坐标绘制左侧月历、右侧 Codex 示例额度及像素宠物。输入固定为参考图中的示例内容，排版以照片为视觉目标：大日期标题、七列日期格、黑红强调、两条额度条和右下角的恐龙场景。中文文字使用本机字体在目标分辨率绘制，数字、进度条和宠物采用适合像素网格的绘制方式。绘制时分别维护黑、红图层的像素归属，文字边缘以确定性阈值取舍，红色在重叠处优先；最终只保留纯白、纯黑、纯红三种像素，不经过照片缩放、误差扩散抖动或二次重采样。预览以整数倍优先放大，并明确标出设备原生分辨率。

生成器只产出可测试的三色像素数据，不持有蓝牙对象，也不发设备命令。普通图片和生成图片通过明确的图片来源状态汇入同一个手动上传入口；原普通图片链路的裁剪及抖动行为不变。当前 `sendimg()` 对文件存在性的检查需要按图片来源拆分，而驱动匹配、槽位覆盖确认、MTU/确认间隔校验、分包失败立即停止和刷新条件继续共用。不得为生成图片另写一套 GATT 写入流程。

## 上传安全边界

自定义视图第一版只支持设备报告的 `0x16`、400×300、黑白红三色配置；条件不满足时仅显示原因，不尝试发送。上传前在本地核对生成结果恰为 120,000 个三色像素，经过现有编码得到各 15,000 字节的黑白与红色平面，且预览与平面解码结果一致。上传仍须由用户手动连接、核对预览并点击一次按钮；槽位已占用时保留覆盖确认。命令顺序沿用当前已验收的 `SET_SLOT`、`INIT`、两平面 `WRITE_IMG` 和 `REFRESH`，任一写入失败就中止，不能自动重试整张图或在失败后刷新。

本功能不发送 `SET_TIME` 日历模式、清屏、固件升级、引脚配置或任意原始命令，不增加自动连接、自动重连和周期任务。软件测试只能证明生成数据及模拟传输链路符合预期，不能保证实体硬件绝对零风险；最后的连接和实体屏显示仍由用户手动验收。

## 验证与完成标准

先增加失败的自动测试，再实现对应行为。测试覆盖默认旧视图、键盘与鼠标标签切换、切换不触发蓝牙 API、连接对象与两种图片状态不互相覆盖、传输中重复操作被拒绝、静态点阵仅含三色、目标尺寸与两平面长度正确、编码/解码回环，以及模拟 BLE 下新图片仍使用旧命令顺序和失败中止规则。原有 Node 与 Python 测试套件都须重跑，网页语法检查与差异检查须通过。

最后在 Edge 本地预览确认窄屏与桌面布局、焦点可见性和原页面无视觉回归。自动测试不连接实体蓝牙，且不把“传输命令完成”表述为“屏幕已显示”；用户对实体屏幕完成单次手动验收后才能确认硬件效果。
